# Timer long press — Issue #26

The existing compact BlueprintCraftTimer and full CraftTimer share `useTimerPress` and `createTimerPress`. Hold for 500ms to open Timer Settings for the selected Build. Movement beyond 10px, pointer cancellation/leaving, page scroll or window blur cancels detection. Cleanup cancels detection and removes global listeners. The following click is suppressed. Touch scrolling remains enabled; native context menu/touch callout is suppressed on editable timer displays where browsers permit it. Normal compact taps continue to start/pause/resume; the full timer retains its existing separate desktop controls. A Timer Settings button and F2 provide accessible alternatives. Informational/completed full timers do not expose editing gestures.

Queue and Build Details settings now open a small reusable modal without leaving the current page. The dialog stages a relative minute adjustment with −1/+1 controls. Apply changes the authoritative selected Build; Cancel/Escape make no edits. Working timers continue running; Paused timers remain Paused. The original crafting duration is unchanged. Completed and Enqueued Builds are not editable, following existing queue rules; an Enqueued dialog explains that the Build must first be started. A blocked Paused compact timer still supports settings while its start action remains blocked.

`adjustBuildTimerMinutes` finds the latest Build in the current queue, ticks its deadline at apply time and uses the existing adjustment engine and changeBuildTimer validation. A Build that expired during configuration is completed, never revived. Subtraction reaching zero follows the existing completion tracker/alarm path. Updates pass through the existing queue persistence mechanism. No new countdown owner or independent timer state was introduced. Blueprint Details currently shows Build rather than a timer, and remains unchanged.

Automated tests cover short tap, 500ms threshold, click suppression, early release, movement, cancellation/cleanup, independent callbacks, selected Build dialog rendering without changes, running/paused adjustments, deadline expiration, completion exactly once, persistence/reload, and desktop settings controls. Existing timer, queue and alarm tests continue passing. Gesture callbacks and dialog rendering use unit mocks/server rendering; mounted browser event/focus behavior still requires manual verification.
