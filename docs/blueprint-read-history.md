# Read / Unread Blueprint tracking — Issue #32

Blueprint names are bold until their Details view is opened, in both Catalog and Collection lists. Only name text changes weight; lineage/strain badges retain their styling. Unread has an accessible text label without a new column. The shared BlueprintDetails component uses a mount/ID effect to request marking the selected canonical ID Read. List rendering, sorting, filtering, searching and acquisition badge controls never call this operation.

An App-level provider shares history across navigation and collections. The repository stores `{version:1,readIds:[...]}` in `wasteland-workshop-blueprint-read-history` through UserStorage. Missing history is empty. IDs are positive safe integers, deduplicated and retained even when absent from the current catalog. Marking is idempotent and saves before updating UI state. Invalid/unsupported saved data blocks history writes and shows a warning; persistence failures leave history unchanged and show an error. Collection membership and acquisition statuses remain independent.

Full backups now use schemaVersion 2 with `blueprintReadHistory`. Version 1 backups explicitly migrate to empty history. Restore replaces history, and the domain participates in transaction journaling/rollback/recovery. Recovery accepts old journals lacking the new domain while preserving its current value. Safety exports include history and restore summaries show the number of Read IDs. New-version backups require the field and retain strict unrelated validation. Older app versions cannot import schema 2 backups; use the updated app for restore.

Automated coverage includes default/unavailable IDs, deduplication/idempotence, failed storage writes, malformed history preservation, name/badge rendering without read callbacks, render-vs-mounted Details distinction, new backup round trips, old-backup migration/replacement, strict validation, and rollback of the new domain. Existing backup recovery, timer, search, acquisition and list tests remain passing.

Manual mounted-browser/phone verification remains required: open/return to both lists; keyboard opening; switching collections; search/sort/filter and status clicks; reload; new catalog IDs; export/restore; restore an older backup; focus and mobile readability. No physical device test is claimed. The browser automation runtime has been unavailable in this session; server-rendered tests do not prove mounted browser interactions. Issue #32 remains open.
