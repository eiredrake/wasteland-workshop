# Warehouse and shopping exports

Warehouse provides Export Warehouse, offering JSON and CSV through the shared ExportDialog. It includes every stored lot, including expired/undated/unavailable items and separate expiration dates, regardless of UI filters, plus credits on hand. JSON has a versioned warehouse report with item IDs, resolved names, quantities, dates and balance. CSV has one balance row and one inventory row per lot so credits are not repeated/summed accidentally. Empty Warehouse can still export its balance. An invalid/unreadable Warehouse disables export to avoid presenting missing data as an empty report.

Each shopping list's existing Export action now offers JSON/CSV for that list, whether or not it is active. Exports include acquired and needed resources, ingredient-choice information and Blueprint targets from the active collection, matching the page's shared Blueprints to Acquire section. CSV includes current resource value estimates, with blanks for unknown values. JSON preserves the existing shopping-list format/version/name/items so Import List still works; separate blueprintCollection and blueprintsToAcquire properties are reference information and do not acquire or import blueprint ownership.

Work History, Warehouse and Shopping reuse ExportDialog, SaveFile and CSV escaping. Save File uses a supported native save-location picker; unsupported browsers use normal downloads (usually Downloads). Cancellation is silent and never triggers a fallback download; errors retain the dialog for retry. Focus returns to the export action. Nothing changes inventory, list quantities, acquired status, active selection, or collections.
